### Problem Statement



> **如何面向端边云 Agentic Workflows，自动生成能够根据 Workflow 与系统证据作出节点 Configuration 和 Device 分配的可执行 Scheduler 策略？**

本文研究的对象不是某一次请求的静态 placement，而是一个可复用、可执行的 Scheduler 策略。该策略接收一个已经规划完成的 Agentic Workflow 及其相关系统证据，为 Workflow 中的每个节点选择执行 Configuration 和 Compatible Device。

### Input

- Agentic Workflow：由 Planner 产生的设备无关任务 DAG，包含任务节点、数据依赖和最终输出。

- 任务 node 内的configuration prefiling 信息：每个任务可选 Configuration 下的 prefiling。

- 不同设备上的profiling：Configuration 在 Device、Edge 和 Cloud 上的执行开销及设备间通信开销。

### Output



输出是**可执行 Scheduler 策略**。对于任意合法的 Workflow 和系统证据，该策略为每个节点返回:



$\text{node} \mapsto (\text{Configuration},\ \text{Compatible Device}).$





### Significance



Agentic Workflow 将多个具有不同语义能力和资源需求的模型与工具组合起来。进入端边云环境后，同一个 Workflow 还会受到设备能力、通信路径和执行 Configuration 的共同影响。因此，调度质量不再只是传统意义上的计算节点 placement，而是语义质量、端到端时延和资源消耗之间的跨层权衡。



现有方法通常依赖专家手工设计规则、问题专用优化器，或者预先定义状态、动作和策略表示的学习方法。这些方案不仅带来较高的建模、调参和训练成本，也限制了系统自动形成新调度逻辑的能力。自动生成可执行 Scheduler 策略，有机会把调度器设计从一次性的人工工程活动转化为由系统反馈驱动的程序搜索过程。

### L1：Agentic Workflow 是一个耦合的优化问题



传统调度问题通常可以预先给定任务结构、运行代价和优化目标。Agentic Workflow 则同时包含三个相互关联的层面：任务依赖决定执行与传输路径；任务 Configuration 影响语义质量；Configuration 与 Device 的组合又决定计算和通信开销。单独优化 placement、模型选择或资源分配，无法完整表达这些决策之间的相互作用。



### L2：现有方法受限于预定义的策略结构



RL 的方法本质上是稀疏的奖励，奖励本身源自于经验设定的量纲和配置。

人工启发式、数学优化和学习型调度方法的求解手段虽然不同，但通常都要求开发者预先规定规则、变量、策略表示或更新机制。人工启发式需要持续投入专家经验；问题专用优化器需要反复建模；RL 等学习方法还需要设计状态、动作、奖励和训练流程，并承担相应的训练与调参成本。

现有方法仍被限制在预定义的策略结构中，没法充分探索整个空间，难以直接从新的执行反馈里形成和修改可执行调度逻辑。

### Design1 Agent 驱动的系统瓶颈探索

本章建立从系统建模、性能证据采集到瓶颈归因的完整分析框架。首先用数学模型描述系统结构、执行过程与性能之间的关系；随后构造能够自适应选择评估对象的性能评估器；最后结合高维切片观测、局部干预和工具调用，设计能够自主收集证据并定位瓶颈的分析 agent。



#### Design1\.1 系统执行与性能关系建模

将系统抽象为由组件、执行路径、资源约束和性能指标组成的结构化模型，该模型既为性能评估提供统一的度量基础，也为后续瓶颈定位限定可分析的变量、依赖关系与干预范围。



#### Design1\.2 基于建模的系统性能评估

基于系统模型构造评估器，使其能够在较低代价下进行节点或执行路径进行测量，并同时量化评估结果的可靠程度。该评估器为分析 agent 持续提供有效的 trace 信息。

##### Design1\.2\.1 基于贝叶斯优化的任务性能 Profiling

利用贝叶斯优化维护系统性能的代理模型，并根据不确定性和潜在性能改进选择下一组 profiling 对象，从而减少低价值实验。

##### Design1\.2\.2 基于信息论的评估可信度量化

通过熵、信息增益或互信息等信息，衡量一次评估对系统性能认知带来的增量，利用这种方法有效解决 profiling 中 accuracy 随任务链传递衰减难以评估的问题



#### Design1\.3 基于切片观测与局部干预的高维瓶颈归因

将系统性能表示为高维空间中的响应函数，通过固定部分变量并观察低维切片，分析性能异常在不同条件下的分布；随后对候选节点进行局部替换或能力提升，比较干预前后的性能变化。切片负责缩小搜索范围，局部干预负责验证因果贡献，两者共同完成从相关性观察到瓶颈归因的过渡。



#### Design1\.4 针对瓶颈诊断的工具增强型分析 Agent

将系统模型、评估器和瓶颈归因方法封装为可调用工具，并设计智能体的分析闭环。智能体根据当前证据提出假设，选择剖析或干预工具执行验证，更新候选瓶颈及其置信度，直至形成包含瓶颈位置、影响路径和证据依据的诊断结果。

##### Design1\.4\.1 瓶颈分析工具集设计

为 Agent 提供切片生成、局部替换、性能比较等结构化工具，使智能体能够通过受约束的操作分析 trace 信息，而不是仅依赖语言模型的主观推断。



##### Design1\.4\.2 工具增强 Agent Pipeline

设计“假设生成—实验选择—工具执行—证据更新—结论验证”的迭代流程，并设置停止条件、冲突证据处理和结果置信度要求，使智能体的分析过程可复现、可解释，也便于控制评估成本。



### Design2 基于特征空间的 LLM 进化式可执行调度策略生成

本章将调度策略搜索建模为特征空间上的质量—多样性进化过程。LLM负责生成具有语义结构的可执行策略代码，特征空间负责描述策略表现和维持种群差异；通过多样化父代选择、覆盖导向的进化算子和跨代经验记忆，在提升策略性能的同时抑制种群收缩、局部最优和跨代退化。

#### Design2\.1 调度策略的行为特征空间建模

将每个调度策略的执行结果映射为特征向量，特征既可包含吞吐量、时延和资源利用率等性能指标，也可包含负载偏好、公平性和调度行为等策略属性。该空间不只是评价策略优劣，还用于描述不同策略“如何工作”，从而识别性能接近但行为机制不同的候选解。



#### Design2\.2 基于特征空间多样性的父代选择

按照多个性能维度和行为特征对策略进行聚类，并在不同聚类之间联合选择父代。选择过程同时考虑策略质量、代表性、差异性和探索价值，并为处于稀疏区域但具有潜力的策略保留进化机会。



#### Design2\.3 面向特征空间覆盖的语义进化算子

##### Design2\.3\.1  目标区域引导的语义变异

根据当前个体与目标特征区域之间的差异，选择需要修改的调度行为，并由LLM生成相应代码变更，从而将随机变异转化为具有方向性的空间探索。



##### Design2\.3\.2 互补行为驱动的策略交叉

选择行为机制互补的父代，识别其可组合的决策逻辑，并通过LLM完成结构化融合。交叉产生能够同时继承不同性能优势的新调度机制。



#### Design2\.4 跨代经验记忆

建立跨迭代记忆，记录历史优秀策略、失败修改。后续迭代在生成候选策略前检索相关经验，以避免重复无效探索和破坏已验证的有效结构

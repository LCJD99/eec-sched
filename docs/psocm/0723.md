## Problem

**面向端边云具身问答智能体的工作流调度策略生成与持续进化**

**EvoScheduler: Evolvable Scheduling**

### Problem Statement

在端边云场景下，实现 **Agentic Workflow 的编排、部署与调度** 是一个关键问题。

### Input

- **具身问答请求**：自然语言问题
- **Workflow 候选组件**：工具库，由多个异构视觉工具组成
  - ResNet
  - ViT
  - Detector
  - Segmenter
  - ...
- **端边云系统状态**：动态变化的物理资源，包括通信、计算等
  - **端侧（Device）**：自己的电脑
  - **边侧（Edge）**：实验室 3090
  - **云侧（Cloud）**：实验室 4090

### Output

- **调度策略（Scheduling Policy）**

### Significance

**面向开放环境的调度策略进化能力。**

---

## SOTA & Limitations

### L1：Agentic Workflow 缺乏跨层调度可见性

场景上，现有的框架在支持此类工作流时仍存在效率低下问题。

核心问题在于：这些工作流将流程表现为一系列不透明的模型调用与工具调用序列，导致**代理逻辑与模型选择及硬件配置之间存在紧密耦合**。

这种设计阻碍了系统对**精度、延迟、能耗及成本**之间的权衡关系进行整体性分析，从而导致资源浪费并降低服务级别目标（SLO）的实现效果。

### L2：现有调度策略缺乏面向开放环境的持续进化能力

技术上，具身问答运行于持续变化的开放环境中，其：

- 任务语义
- Workflow 结构
- 可用模型与工具
- 资源条件
- 服务目标

均可能发生**分布外（Out-of-Distribution, OOD）变化**。

因此，调度器不仅需要根据瞬时系统状态进行动态决策，还需要持续更新其**知识、策略结构和能力边界**。

现有启发式和学习型调度方法大多采用**闭世界假设（Closed-world Assumption）**：

- **启发式方法**：依赖人工预定义规则；
- **学习型方法**：通常在固定的状态空间、动作空间和奖励函数中学习，并在部署后冻结策略。

它们能够对已知变化作出反应，但缺乏面向**未知任务和新系统能力**的持续策略演化机制。

## Rationale / Opportunity / Insight

### L1 → O1：从不透明调用序列到可声明、可调度 Workflow

引入 **Declarative Workflow Abstraction**，将：

- 任务逻辑
- Workflow 依赖
- 执行配置

进行解耦，使调度器获得 **cross-layer visibility**。

进一步暴露以下 **control knobs**：

- Workflow structure
- Model / Tool routing
- Placement
- Resource budget
- Execution configuration

从而使 LLM 能够基于统一抽象生成跨层调度策略。

### L2 → O2：从部署后冻结策略到可持续进化策略

具身问答 Workflow 的实际执行能够产生细粒度诊断信息，例如：

- 错误的 Tool Routing
- 无效验证（Redundant / Ineffective Verification）
- 云端调用收益不足
- Edge Overload
- Deadline Risk
- Fallback Failure

这些执行信号可以被结构化为 **Structured Diagnostics**，并由 LLM 离线分析，用于持续修改和进化调度策略代码。

## Model / Design

### C1 → M1：LLM-driven Scheduling Policy Generation

引入 **Declarative Abstraction**，实现 LLM-driven 调度策略生成。

#### Module 1：端边云调度算子库构建

构建统一的 Scheduling Operator Library，为策略生成提供标准化的调度操作接口。

#### Module 2：策略模板构建

设计统一的 Scheduling Policy Template，使 LLM 能够基于：

- Workflow
- System State
- Scheduling Operators
- Scheduling Objectives / Constraints

生成可执行的调度策略。

---

### C2 → M2：Continual Policy Evolution with Structured Diagnostics

#### Module 1：执行反馈的结构化构建

将 Workflow 执行过程中产生的反馈转换为结构化诊断信息，例如：

- Task-level feedback
- Tool-level feedback
- Resource-level feedback
- SLO violation
- Scheduling decision outcome

#### Module 2：进化经验生成

根据 Structured Diagnostics，由 LLM 分析：

- 当前策略的问题
- 性能瓶颈
- 成功 / 失败决策
- 潜在策略改进方向

并生成可复用的 **Evolution Experience**。

#### Module 3：策略进化

基于：

> Current Policy + Structured Diagnostics + Evolution Experience

生成新的 Scheduling Policy，并通过评估反馈持续迭代：

> **Generate → Execute → Diagnose → Reflect → Evolve → Evaluate**

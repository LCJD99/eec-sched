# Design 1：自进化 Agent 驱动的 AIWaaS 调度瓶颈探索

## 1. 研究目标与系统边界

AIWaaS 将用户请求表示为工具调用工作流，并将工作流中的每个节点映射到具体模型配置与端、边、云设备。瓶颈探索的任务不是直接生成新调度策略，而是回答：**当前策略在哪些工作流结构、输入与系统状态下作出了损害性能的决策；局部改变该决策能否稳定改善端到端结果**。诊断输出随后成为 Design 2 的语义变异或交叉依据。

系统分为工作流规划、性能证据、可信评估和瓶颈分析四层。规划器依据请求生成工具调用 DAG；调度器在给定 DAG 上选择 Configuration 和 Compatible Device；Profiling Database Snapshot 提供可重放的质量、执行和传输证据；可信评估器计算结果；分析 Agent 只能通过受控工具读取证据和提出反事实干预，不能修改评估规则。当前仓库已建立这些边界，以下设计在其上补全自适应测量、信息论精确性评估和诊断工具进化。

全文使用“节点”指工具调用 DAG 中的任务节点，使用“Scheduler Candidate”指一版可执行调度策略。一次 Trace 是一个请求、DAG、调度提案及其可信评估结果的组合。

## 1.1 AIWaaS 系统模型与性能评估

### 1.1.1 调度空间、执行过程与目标

设请求为 $x$，系统状态为 $s$。规划器给出工作流 $W=P(x)$，其中 $W=(V,E)$ 是有向无环图；节点 $v\in V$ 指定工具类型 $t_v$，边表示数据依赖。对工具 $t_v$，有限的、预先验证的联合配置集合记为 $\mathcal C(t_v)$。配置 $c$ 包含模型版本、精度、推理参数及其他会影响质量或执行的选择；它是不可再拆分的调度单位。设备集合为 $\mathcal H(s)$，兼容关系 $K(t_v,c,h,s)\in\{0,1\}$ 同时考虑软件支持、配置可运行性与当时资源状态。

调度器对固定 $W$ 返回节点分配

$$
A=\{(c_v,h_v):v\in V\},\qquad
A\in\Omega(W,s)=\left\{A\mid c_v\in\mathcal C(t_v),\ h_v\in\mathcal H(s),\ K(t_v,c_v,h_v,s)=1\right\}.
$$

因此完整系统的决策可写作 $\pi(x,s)=(W,A)$，但本研究中的 **Scheduler Candidate 只求解 $A$**；$W$ 由上游规划器确定。工作流变化会改变节点数、依赖与可选配置，设备和状态变化会改变可行集合，所以跨请求观察到的是开放、可变维空间，而单条 Trace 的调度提案具有固定维度。基础实验以 `device`、`edge`、`cloud` 三设备和固定 Input Bucket 建立可重放对照；状态分层实验再比较负载和设备变化。

对节点执行时间 $d_v(c_v,h_v,s)$、边传输时间 $d_e(h_u,h_v,b_{uv},s)$ 与调度求解时间 $T_{\rm sched}$，可信模拟器按依赖顺序执行，并在设备队列和有向传输链路上串行化冲突操作。设模拟完成时间为 $T_{\rm exec}(W,A,s)$，总时延为

$$T(W,A,s)=T_{\rm sched}+T_{\rm exec}(W,A,s).$$

资源量 $R(W,A,s)$ 采用各节点 Execution Profile 中 GPU 显存 MiB 的求和；传输只贡献时延。质量 $Q(W,A,x)$ 表示最终输出相对于任务目标的保守质量估计。三者组成可解释的指标向量 $m=(Q,T,R)$。当前可信评分使用

$$
S(W,A)=\bar w_Q Q+\bar w_T\frac{1}{1+T/L}+\bar w_R\frac{1}{1+R/M},
\qquad \sum_i\bar w_i=1,
$$

其中 $L,M>0$ 是固定尺度，权重非负。有效性来自依赖、Configuration 兼容性与完整分配校验；评分中的三个指标本身没有硬阈值。诊断保留原始指标与节点分配，不能只凭一个综合分数判断瓶颈。

### 1.1.2 可重放证据与自适应 Profiling

性能评估分为**离线测量**与**在线重放**。前者执行真实模型，后者仅使用冻结的 Profiling Database Snapshot 评估大量 Scheduler Candidate。快照包含每个可调度 Configuration 的 Quality Profile、每个兼容 Configuration–设备对的 Execution Profile、所有有向跨设备路径的 Transfer Profile，以及测量范围、来源、样本数和摘要。Quality Profile 保存任务原始指标、置信区间、归一化质量下界及输出大小；Execution Profile 保存 warm p95 时延和峰值 GPU 显存；Transfer Profile 保存传播时延和带宽。真实测量与合成数据不能混用为同一快照。

为避免穷举高维配置，先按工具进行多目标贝叶斯优化。设配置参数向量为 $z$，观察值为 $y(z)=(q(z),-\ell(z),-r(z))$，其中质量指标按方向转换为“越大越好”。以固定样本、输入桶、随机种子及硬件环境测量初始 Sobol 点；用多输出高斯过程拟合成功观测，使用带噪预期超体积改进（qNEHVI）选择下一候选配置；非法、重复、OOM 或测量失败都记录原因，不伪造目标值。采集函数的后验不确定性与预期 Pareto 改进共同决定实验价值。每轮保存提案、模型版本、采集值、测量与来源，预算用尽后从成功且唯一的配置中保留覆盖质量、时延和资源权衡的目录。

配置发现与快照发布之间还有一道必要的测量关口：保留配置须在每个声明兼容的设备上完成 Execution Profile，并补齐质量置信区间和全部有向传输 Profile，方可生成 `measured` 快照。运行期间若状态 $s$ 偏离冻结测量范围，应创建带新来源的快照或状态分层 Profile，不能悄悄改写旧快照。

Agent 的主动测量按“最可能改变诊断结论的实验”选择，而不是对所有节点平均投入预算。对待测对象 $e=(t,c,h,b)$ 定义

$$
a(e)=\frac{\mathbb E[\Delta U_{\rm diagnosis}\mid e]+\lambda\,\mathbb E[\Delta HV\mid e]}{\operatorname{cost}(e)},
$$

其中 $\Delta U_{\rm diagnosis}$ 是测量后候选瓶颈排序的不确定性下降，$\Delta HV$ 是配置 Pareto 前沿的预期改进。离线 BO 负责目录发现；在线诊断阶段若允许新增测量，只向独立测量服务提交请求，待新快照验证通过后重新评估，不让 Agent 直接修改正在使用的证据。

### 1.1.3 信息论驱动的任务链精确性评估

可重放评分先把最终输出依赖锥中各节点的归一化质量下界相乘：$Q_{\rm base}=\prod_{v\in\operatorname{Anc}(O)}q_v^{\rm LCB}$。它是一种保守的组合代理量，但节点质量指标异构，也不能辨别上游信息在下游被保留还是恢复。因此评估器增加**任务属性信息损失**证据，并以端到端任务指标校准质量估计；不把互信息数值直接当作准确率。

对每类工作流定义可验证的目标属性 $Y$（例如图像类别、问答答案、文本实体或 OCR 字符序列）及固定的成对样本 $D=\{(x_i,y_i)\}$。执行候选配置时，在每个节点保存仅供评估的中间输出 $Z_v$；多父节点的输入写为 $Z_{\mathrm{pa}(v)}$。$C$ 表示事先声明的任务类别或提示模板等上下文，不能包含完整请求及答案。在同一批样本上估计

$$
I_v^{\rm in}=I(Y;Z_{\mathrm{pa}(v)}\mid C),\quad
I_v^{\rm out}=I(Y;Z_v\mid C),\quad
\Delta I_v=I_v^{\rm out}-I_v^{\rm in}.
$$

$\Delta I_v<0$ 表示该节点相对于其输入丢失了与任务目标相关的信息；它作为定位线索，而不是跨不同模态直接比较的统一“准确率”。任务上下文 $C$ 的选择需要避免泄漏答案或使条件互信息退化。离散标签可采用交叉熵或经校准的概率预测器估计 $H(Y\mid Z,C)$；文本、图像等高维表示先冻结任务相关的评估器或属性抽取器，再在独立验证集上校准估计偏差。每项估计记录样本数、估计器版本和 bootstrap 置信区间。

最终质量仍以可观测端到端指标 $m(Y,\hat Y_A)$ 为锚：

$$
Q_{\rm e2e}(A)=\operatorname{LCB}_{1-\alpha}\!\left(\{m(y_i,\hat y_i(A))\}_{i=1}^{|D|}\right).
$$

信息损失向量 $(\Delta I_v)$ 用来选择复测节点、解释链式衰减，并辅助在端到端标注稀缺时训练校准模型 $\hat Q(A\mid q_v,\Delta I_v,W)$。校准模型只能在未参与拟合的工作流与样本上验证；未通过校准时继续使用 $Q_{\rm base}$ 并报告信息论诊断为辅助证据。只有在独立样本上通过校准检验后，才能以版本化评分规则将 $\hat Q$ 或 $Q_{\rm e2e}$ 纳入可信评分，并在同一规则下重新评估所有待比较 Candidate。这样既有可执行的质量评分，又不会将缺乏统计保证的互信息乘积误称为真实准确率。

## 1.2 自进化瓶颈分析 Agent

### 1.2.1 三类元工具与证据契约

Agent 接收某 Scheduler Candidate 的 Candidate Evaluation Evidence：每条 Trace 的 DAG、节点分配、模拟节点和传输时序、质量、时延、资源、综合分数，以及快照摘要。初始上下文只给压缩索引；Agent 调用工具按需读取完整 Trace。所有工具返回结构化结果、快照标识和可引用的 Trace/节点证据。

| 元工具 | 输入 | 输出及作用 |
| --- | --- | --- |
| Profiling `profile_trace` | `trace_id`、关注维度、`top_k` | 关键路径近似、节点/传输热点、替代 Configuration 与设备、原始指标、证据引用；只观察，不作因果断言。 |
| Intervention `intervene_assignment` | `trace_id`、局部节点分配补丁 | 在相同 DAG、输入与快照上重新调用可信评估器，返回基线与反事实的 $\Delta Q,\Delta T,\Delta R,\Delta S$。 |
| Validation `validate_intervention` | 多条 Trace 上的显式补丁 | 汇总跨 Trace 的变化、有效样本数、失败原因及异质性；在独立负载/状态层重复真实测量。 |

干预工具只接受合法且完整的节点分配，不修改 Scheduler Candidate 源码、快照或评分函数。验证分两层：先在固定快照上做确定性反事实重放，筛除无效假设；再由实验执行器在独立请求、负载档位和状态快照上重测，保留配对基线、方差及置信区间。第一层的效果不能单独证明真实环境中的因果改善。

### 1.2.2 假设生成、主动干预与诊断停止

诊断对象是候选瓶颈 $b=(\text{位置},\text{机制},\text{影响路径})$，例如“关键路径上的边缘节点采用慢配置”“云端放置造成请求与结果双向传输”“质量较低的上游 Configuration 损失任务信息”。Agent 先由 Profiling 产生可检验假设，再优先选择预期信息增益高且代价低的局部补丁。对每个假设保留支持与反证：跨 Trace 的配对分数差、原始指标变化、关键路径变化、输入和状态分层，以及无效或失败干预。

每轮执行“提出假设 → 选择工具 → 获取可信结果 → 更新假设”。给定历史证据 $E_k$，维护 $p_k(b)=P(b\mid E_k)$；一次工具调用的优先级可写为

$$
u(a)=\frac{H(p_k)-\mathbb E_{o\sim a}[H(p_{k+1}\mid o)]}{\operatorname{cost}(a)}.
$$

初始先验可由热点排序给出，后验依据预先声明的效果方向、配对差值分布和失败率更新。报告的 `confidence` 必须基于可复核的统计证据或清楚标为启发式；不能把 LLM 自报的确信程度视为概率校准。停止条件为：关键假设已在预设验证集上达到效果阈值且置信区间排除零、工具预算耗尽、或新调用的预期信息增益低于阈值。最后输出 `bottlenecks`、`impact_path`、`evidence`、`confidence` 与可供 Design 2 使用的修改建议；证据不足时明确返回未确认假设。

### 1.2.3 从历史轨迹进化专用诊断工具

每次诊断记录场景摘要、快照摘要、工具名与参数、结果引用、结论和后续验证效果。对反复成功的调用轨迹，Agent 提出可复用的复合工具。例如“关键路径资源分配检查”依次调用 `profile_trace(focus="latency")`、对占比最高节点运行 `intervene_assignment`，再在相似 Trace 上调用 `validate_intervention`。复合工具以声明式步骤、参数占位符和版本号保存；运行时只能调度上述受控元工具。

工具进化采用提议、回放、发布三步。首先从至少三条不同工作流或输入层的成功轨迹归纳步骤和适用条件；随后在未参与归纳的保留 Trace 集上回放，比较诊断正确率、无效调用率、工具成本与错误归因率；只有效果超过通用元工具基线并通过参数与输出边界检查，才加入可调用工具目录。若新快照或任务类型导致效果退化，降低优先级或撤回工具。

### 1.2.4 与调度策略进化的闭环

Design 1 对每个已评估的 Scheduler Candidate 输出基于证据的 Bottleneck Diagnosis。Design 2 用它限定代码生成的修改目标，生成新 Scheduler Candidate 后仍由同一个可信评估器在固定 Evolution Trace Set 上评分，并在独立 Final Evaluation Trace Set 上检验最终选择。若新候选失败或退化，其记录反过来更新诊断假设与工具评价。诊断侧的快照版本、样本集合和评分规则在一次比较中必须固定，避免把证据漂移误判为策略改进。
